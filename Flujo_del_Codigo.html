Cómo se entrena y cómo funciona cada parte del detector de fraude

Guía de uso del código del repositorio deteccion-fraude-financiero-ia: qué comandos correr, qué pasa por dentro en cada módulo y cómo leer lo que sale.

1. Ponerlo a funcionar en tres pasos

El modelo no viene "pre-entrenado" guardado en un archivo: se entrena cada vez que corres main.py, porque tarda menos de un segundo. Entrenar y ejecutar son el mismo comando.

Instalar las dependencias (una sola vez)

cd codigo
python3 -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt  # numpy, pandas, scikit-learn, matplotlib

Necesitas Python 3.10 o superior. En el Mac del proyecto ya existe el entorno: ../.venv/bin/python main.py.

Entrenar, evaluar y generar las alertas

python main.py

Imprime cuatro bloques (datos, entrenamiento, evaluación, alertas) y deja todo en la carpeta salidas/: métricas, cuatro gráficos, el archivo de alertas y la bitácora completa. Tarda unos 10 segundos.

Ver el sistema trabajando transacción por transacción (para el video)

python main.py --demo --demo-n 20 --pausa 0.8 --sin-graficos

Entrena igual que antes y luego muestra 20 transacciones llegando una a una, con color por nivel y los motivos de cada alerta. --pausa son los segundos entre líneas.

Para confirmar que todo está bien antes de grabar: python -m unittest test_basico -v debe terminar con OK y 4 pruebas.

3. Qué significa "entrenar" aquí

Es aprendizaje no supervisado. No le mostramos al modelo ejemplos de fraude para que los memorice (hay muy pocos y el fraude cambia). Le mostramos 48.000 transacciones de los primeros 24 días y le pedimos que aprenda cómo se ve lo normal. Después, cualquier transacción que se aleje de eso recibe una puntuación alta.

Por eso el entrenamiento es tan rápido y por eso no hay un botón de "seguir entrenando": el modelo se reentrena por lotes cuando hay datos nuevos, no con cada transacción. Reentrenar en vivo con lo que va llegando sería un riesgo real: un defraudador podría enseñarle poco a poco que su patrón es normal.

Entrenar con tus propios datos

python main.py --csv mis_transacciones.csv
python main.py --csv creditcard.csv      # dataset público de Kaggle, se detecta solo

Un CSV propio debe tener las 11 columnas del modelo (monto, hora, fin_de_semana, distancia_km, tx_ultima_hora, ratio_monto, pais_distinto, dispositivo_nuevo, comercio_nuevo, intentos_pin, canal) y, si quieres métricas, la columna es_fraude con 0 o 1.

Perillas que cambian el comportamiento

--n 100000
Cuántas transacciones sintéticas generar.
--fraude 0.002
Proporción de fraude en los datos sintéticos y parámetro contamination del Isolation Forest.
--presupuesto 0.01
Fracción de transacciones que el equipo humano puede revisar. Define el umbral del nivel ALTO. Subirlo detecta más fraude y genera más falsos positivos.
--presupuesto-medio 0.03
Fracción que recibe verificación OTP (nivel MEDIO).
--modelo iforest
Entrena solo un modelo (iforest, autoencoder o ambos).
--semilla 42
Cambiarla produce otro conjunto de datos; dejarla igual hace el experimento repetible.

4. Qué hace cada archivo

datos.py
Fabrica el conjunto de datos o lo carga de un CSV.

generar_transacciones() crea clientes con un gasto promedio propio y les genera compras normales: montos lognormales, horas diurnas, cerca de casa. Mezcla también comportamientos legítimos que se parecen al fraude (viajeros, compras grandes) para que el problema sea realista. Luego inserta los fraudes con cuatro patrones:

card_testing
Muchos micro-cobros seguidos por web desde un dispositivo nuevo.
toma_de_cuenta
Monto grande de madrugada, dispositivo nuevo, varios intentos de OTP.
tarjeta_clonada
Compra presencial a cientos o miles de km, muchas veces fuera del país.
fraude_sutil
Imita lo normal: monto pequeño, hora normal, cerca del cliente. Es el que el modelo casi no detecta (11 %).

Todo sale de un generador con semilla fija, así que no hay datos de personas reales y la corrida siempre es la misma.

modelo.py
Los dos detectores, con la misma interfaz entrenar(X) y puntuar(X).

Isolation Forest construye 300 árboles que parten los datos con cortes al azar. Una transacción rara queda sola en pocos cortes; una normal necesita muchos. La profundidad media a la que se aísla, invertida, es el score. Es el modelo principal porque obtuvo el mejor AUC-PR (0,83).

Autoencoder es una red neuronal 11 → 8 → 3 → 8 → 11 entrenada para reconstruir su propia entrada (MLPRegressor de scikit-learn, 60 épocas). Como solo ve transacciones mayormente normales, reconstruye mal las fraudulentas, y ese error cuadrático es el score.

La clase base hace dos cosas que ambos comparten: estandariza las variables con StandardScaler y convierte el score crudo en un percentil respecto al entrenamiento. Así un score de 0,99 significa "más anómala que el 99 % de lo que vimos al entrenar", sin importar el modelo, y los umbrales de alertas sirven para los dos.

evaluacion.py
Mide con las métricas correctas para una clase rara y dibuja los gráficos.

Con 0,5 % de fraude la exactitud engaña: decir "todo es legítimo" acierta el 99,5 %. Por eso se reportan AUC-ROC, AUC-PR (la métrica honesta, el azar daría 0,004), precisión, recall, F1 y la matriz de confusión. umbral_por_presupuesto() fija el umbral como el cuantil del score que deja pasar solo el 1 % más anómalo. recall_por_tipo() dice qué patrón de fraude se detecta y cuál no. graficar() produce las cuatro imágenes de salidas/graficos/.

alertas.py
Convierte el score en una acción proporcional y deja todo en bitácora.
BAJO · score < 0,97Aprobar y registrar. El 97 % de las transacciones.
MEDIO · 0,97 a 0,99Aprobar y pedir OTP o confirmación push al cliente. Si confirma, la alerta se cierra.
ALTO · score ≥ 0,99Retener solo esa transacción, avisar al cliente y escalar a un analista humano con plazo de 2 horas.

El modelo nunca bloquea una cuenta. Si un mismo cliente acumula dos alertas ALTAS, el sistema propone un bloqueo preventivo, que sigue marcado como pendiente de analista. explicar() toma las tres variables más alejadas de la media de la población legítima (z-score) y las escribe en lenguaje claro: "14 transacciones en la última hora; dispositivo nunca visto". Cada decisión queda en bitacora_decisiones.csv con score, nivel, acción, motivos y estado.

main.py
Orquesta todo y ofrece la línea de comandos.

Lee los argumentos, carga o genera los datos, divide en pasado y reciente, entrena los modelos pedidos, evalúa, elige como principal el de mayor AUC-PR, construye los umbrales, pasa las transacciones recientes por el sistema de alertas y guarda las salidas. Con --demo reemplaza el procesamiento por lotes por una simulación que mezcla fraudes reales, algún viajero de nivel MEDIO y transacciones normales para que en el video se vean los tres colores.

test_basico.py
Cuatro pruebas que protegen lo que se va a mostrar.

Que los datos sean desbalanceados y reproducibles, que Isolation Forest supere al azar con margen (AUC-ROC > 0,9 y recall > 0,5), que el autoencoder devuelva scores entre 0 y 1, y que el sistema de alertas nunca bloquee sin marcar revisión humana.

6. Si algo falla

ModuleNotFoundError
El entorno virtual no está activo o faltan dependencias. Repite el paso 1 y verifica que el prompt muestre (.venv).
Python 3.9 o menor
El código usa sintaxis de tipos moderna. Instala Python 3.10 o superior y crea el entorno con esa versión.
"Matplotlib is building the font cache"
Solo pasa la primera vez y tarda unos segundos. No es un error.
Colores raros en la demo
Son códigos ANSI de la terminal. Usa Terminal, iTerm o Windows Terminal, no la consola de un IDE antiguo.
Los números no coinciden con el resumen
Revisa que no hayas cambiado --semilla, --n, --fraude ni --presupuesto. Los valores por defecto reproducen la corrida de referencia.
